# 官方商城选择应用后创建多任务卡片

- 状态：已采纳
- 日期：2026-10-05

## 行为与边界

官方商城的“立即使用”代表创建一张应用任务卡片。每次点击生成独立请求和独立卡片，即使应用 ID 相同也不复用已有卡片。应用层切换到多任务视图；工作区填入 ID、使用当前消费级 API 配置加载参数，并将新卡片滚动到可见位置。任务仍由用户手动点击运行。

商城协议数据只在首页提取应用 ID；跨视图只传递请求 ID 和应用 ID，不传递 API 凭据或直接调用任务提交接口。请求队列仅保存在页面内存中，不在刷新后重放。标准模型和收藏入口保留各自的现有职责。

## 请求交付和状态归属

应用层维护待创建请求队列，多任务工作区负责消费并按请求 ID 确认移除。创建请求同步标记为已消费；请求 ID 同时作为新卡片 ID，防止 React StrictMode 效果重放或重渲染重复创建。多个真实点击拥有不同请求 ID，因此不会相互覆盖。

卡片继续归多任务工作区维护，消费方复用已有预设创建、加载入口。首次加载失败或 API 未配置时仍保留卡片和 ID，用户在同一卡片重试。应用容器的设置归一化、状态及视图分离到独立模块，保持文件在 500 行内。

## 异步加载约束

每张卡片的每次加载拥有独立令牌。更改应用 ID、删除卡片、加载草稿均使旧令牌失效；成功和错误回调只更新当前令牌对应的卡片。实际卸载后忽略结果，但保留令牌跨过 StrictMode 的同步清理与重新挂载，防止首次请求结果被误丢弃。

## 验证与回滚

隔离浏览器夹具在 5184 端口使用虚构消费级和企业级 API，拦截远端请求，验证真实商城导航、重复选择、连续入队、StrictMode、失败重试、缺少配置以及删除和编辑时的旧请求返回。任何任务提交均计为测试失败。

该变更不涉及存储迁移；回滚代码即可恢复原入口行为。现有卡片草稿、运行历史与目录设置格式不变。
