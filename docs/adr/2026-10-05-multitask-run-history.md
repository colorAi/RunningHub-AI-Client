# 多任务运行历史与结果下载

- 状态：已采纳
- 日期：2026-10-05

## 决策

多任务每次启动为每张卡片创建独立运行记录；一次批量运行将其子任务作为同一记录中的多个单元。单卡运行也写入多任务历史。普通模式的历史仍使用现有模型。

运行记录保存在应用来源对应浏览器配置或桌面 WebView 的 IndexedDB 中。记录仅包含卡片和应用标识、批次名、开始结束时间、任务 ID、单元状态、结果 URL、用量和安全错误摘要；不保存输入文件、API 密钥、密码或原始运行日志。IndexedDB 之外保留页面内存快照，使存储故障不会改变任务结果；界面提示保存失败并提供重试。

子任务提交成功后立即保存任务 ID，再验证提示信息。完成、失败、停止事件按运行 ID 和单元序号更新；容量重试继续使用原记录。刷新后未结束的记录显示“未继续追踪，服务端状态待确认”，不会自动重跑或轮询。Web Locks 标识当前浏览器配置中仍持有运行锁的记录，阻止误删或并发覆盖。没有 Web Locks 的环境对未结束外部记录采取保守保护。

历史按运行记录展示，支持按卡片筛选、名称搜索、状态过滤、分页、展开任务和结果、单文件下载、单次 ZIP 和多次合并 ZIP。合并时每次运行使用独立目录。失败文件可重试，已成功文件保留在部分 ZIP 中。下载开始时固定记录和输出快照；获取链接失败不自动重跑服务端任务。

目录句柄按卡片 ID 保存在多任务页面状态中，因此当前页面内卡片下载与其历史下载复用同一目录。关闭页面后需重新选择；跨卡片合并下载单独选择目标目录，不修改各卡片设置。桌面 Tauri 和浏览器文件系统能力继续使用项目已有实现。

## 边界与影响

运行记录是本机浏览器配置的数据，不会跨设备同步。删除记录只删除本地元数据，不删除已写入目录的文件，也不取消远端任务。URL 是下载所必需的凭据型数据，保存在本机 IndexedDB；错误摘要使用错误码白名单，其他错误统一化，避免将令牌或输入内容写入历史。

历史功能从启用后开始记录，无法恢复先前未保存的运行。链接可能过期或因远端权限改变而失效，下载界面保留失败项目并允许重试。

## 验证

模型与控制器测试覆盖并发乱序、重复事件、容量重试、停止、刷新、存储失败、损坏行和删除保护。浏览器隔离夹具验证 IndexedDB、多卡筛选、分页、同卡目录复用、跨卡目录选择、ZIP 分组、文件下载、取消、权限失效与恢复。不提交 RunningHub 任务。
