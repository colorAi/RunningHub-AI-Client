# 卡片管理、可复用配置与当前任务总览

## 决策与边界

顶部“卡片管理”独立入口包含“我的卡片库”和“当前任务”。卡片库保存可复用配置；当前任务是已有会话卡片的投影，不新建执行上下文。应用封面来自已有 `WebAppInfo.covers`，无封面或读取失败显示图标，不上传自定义图片。

卡片可以加入多个组，并附加多个自定义标签。组拥有稳定 ID，重命名同步所有引用，删除组仅移除关系。模板的分类和使用它新建的任务分类是独立快照，不隐式双写；更新模板需要显式执行“更新已保存卡片”。标签在每张卡片中保存文本，通过已有文本提供建议。

工作区、调度器、历史与编辑器仍由常驻的多任务容器持有。展示模式切换使用可见性控制，保持编辑器挂载，保存未提交参数、本地 File 对象、运行上下文和目录句柄。库中“使用”创建新 ID，并导航定位；当前任务“打开卡片”定位已有 ID。两种导航都不提交任务。

## 数据与持久化

独立 IndexedDB 数据库 `rh_card_library_v1` 使用 `cards`、`groups` 和 `meta` 三个对象仓库。读取时验证并重建白名单模型，存储操作以事务完成后才视为成功。保存卡片校验组 ID，更新已删除卡片报错而非复活。组删除和库内引用清理使用同一事务，当前任务分类在读取新目录后按存活组 ID 清理。多窗口通过 BroadcastChannel 与窗口聚焦刷新数据，防止加载结果反向覆盖较新的读取。

配置包含应用信息、节点参数、批量行、实例类型、保留时间和分类；不包含 API 配置、访问口令、任务 ID、结果、运行日志、目录权限或待上传文件。保存读取最新编辑器快照，不能优先复用上次运行的旧参数。正在上传时拒绝保存；对待上传批量文件清空相应参数，对 blob/data/file 预览地址同样清空，并保留需重新选择文件的提示。已上传文件的服务端引用可保留，过期后仍需在任务中重新上传。

作用域沿用现有客户端的浏览器 origin／本地配置环境，不按 API Key 分割，也不新增云端用户系统或跨设备同步。卡片库持久化；当前任务依然属于当前会话，运行历史继续使用原存储。

## 旧草稿与故障处理

首次读取卡片库在一个读写事务内检查迁移标记，将每份旧草稿转为同名组、组内每张卡片转为独立模板。记录 ID 来自源草稿 ID 和行序号，相同应用的不同配置不合并。写入模板、组和完成标记在同一事务内完成，多个窗口、StrictMode 和重试不会重复导入。

原草稿数据仍保留在原键中，原有整体保存／加载草稿功能继续存在；首次导入后不会自动同步新草稿，以免覆盖用户在库中的编辑。旧草稿本身未保存 File 对象，导入不能恢复当时未上传的文件。读取异常时显示重试入口，不标记迁移成功。工作区初始化不再把读取失败产生的空列表写回源存储。

保存失败保持编辑对话框及输入；删除模板不影响已有任务或历史。回滚功能代码时可保留新数据库，不需要修改旧草稿或运行历史。

## 验证

- `node --test tests/cardLibrary.test.mjs`：配置隔离、敏感字段排除、待上传文件清理、组合筛选、异常草稿和独立任务 ID。
- 隔离浏览器：在端口 5185 打开 `/tests/fixtures/card-management.html`。该 fixture 只读写隔离 origin 数据，拦截外部 API，模拟目录句柄，不提交收费任务。
- 浏览器覆盖并发迁移、失败后重试、更新已删除模板、多个组与标签筛选、复制删除、最新参数更新、重新挂载恢复、运行状态及本地文件／目录保留。
- 回归商城“立即使用”、运行历史、ZIP 下载及目录选择；检查 TypeScript 与生产构建。
